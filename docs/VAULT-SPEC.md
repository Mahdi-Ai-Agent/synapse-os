# Vault specification v0.1

A Synapse vault is a folder of Markdown files plus a thin agent layer. It is the source of truth; everything under `index/` and `.synapse/` is derived or app-private. Default location `~/Synapse/vault` (never inside the code repo).

## Layout

```
vault/
├── AGENTS.md                 # brain instructions (canonical, cross-tool)
├── CLAUDE.md                 # @AGENTS.md + @memory/profile.md + @memory/lessons.md
├── .claude/
│   ├── rules/                # paths-scoped authoring rules per node type
│   ├── skills/{capture,ask,link,advise,make,character,daily,weekly,insight,review}/  # SKILL.md + references/
│   ├── hooks/guard-paths.sh  # PreToolUse: Write/Edit only under nodes/ and memory/
│   └── settings.json
├── nodes/
│   ├── notes/ ideas/ tasks/ projects/ goals/ habits/ areas/ people/ events/ journal/ resources/
│   └── inbox/                # raw captures, consumed by /capture
├── memory/
│   ├── profile.md            # who the owner is (short, always loaded by the brain)
│   ├── insights.md           # what the brain sees in the owner, written by /insight (shown on the Me page)
│   ├── focus.md              # what to spend time on now, written by /review (the coach's Now; read by /daily)
│   ├── places/<file>.md      # one category's or island's analysis, written by /insight [[Place]] → <file> (its page's Analysis)
│   └── lessons.md            # what the brain learned (NEVER/ALWAYS lines)
├── index/                    # GENERATED by the app; gitignored; brain never writes here
│   ├── INDEX.md
│   ├── by-type/<type>.md
│   ├── by-area/<area>.md     # one file per category: every item in it, one line each
│   ├── archive.md            # the retired items (archived, dropped, finished 30+ days ago), read only for the past
│   └── graph.json
├── .synapse/                 # app-private; gitignored
│   ├── settings.json         # engine, per-engine model/effort, locale, graph prefs, API keys, server.lanAccess (mode 600; served masked)
│   ├── pairing.json          # phone pairing token (mode 600; docs/ARCHITECTURE.md "Access control")
│   ├── connections.json      # apps connected over MCP and personal keys, tokens as hashes (mode 600; docs/ARCHITECTURE.md "MCP connector")
│   ├── engine-sessions/      # API engines: one JSON transcript per engine session (<engine>/<uuid>.json)
│   ├── sessions.json         # threadId → engine session id, messages
│   ├── suggestions.json      # dismissed related-node pairs ({a, b, at})
│   ├── layout.json           # where the user left the map: region anchors, pins, positions (docs/ARCHITECTURE.md "Layout")
│   ├── previews.json         # cached link previews (docs/ARCHITECTURE.md "Link previews")
│   ├── backups/              # what an import replaced, as zips (the last three; docs/ARCHITECTURE.md "Backup")
│   ├── runtime-context.md    # written before each brain run
│   └── cache/
└── .gitignore                # index/ .synapse/ .DS_Store
```

## Node files

Path `nodes/<dir>/<slug>.md`. Directory by type: note→`notes`, idea→`ideas`, task→`tasks`, project→`projects`, goal→`goals`, habit→`habits`, area→`areas`, person→`people`, event→`events`, journal→`journal`, resource→`resources`, inbox→`inbox`.

**Slug:** title → Unicode NFC → replace whitespace and `/ \ : * ? " < > | # ^ [ ] %` with `-` → collapse repeated `-` → trim `-` → lowercase Latin letters → max 80 chars. Non-Latin scripts (Persian) are kept as written. On collision append `-` + last 4 chars of the id. Journal files are `YYYY-MM-DD.md`. Inbox files are `YYYYMMDD-HHmmss-<slug>.md`. The file name is fixed at creation and survives renames (see **Renames**).

**Frontmatter** (YAML, keys in English):

| Field | Type | Required | Applies to | Notes |
|---|---|---|---|---|
| `id` | string | yes | all | ULID, immutable, the stable key |
| `type` | enum | yes | all | `note` `idea` `task` `project` `goal` `habit` `area` `person` `event` `journal` `resource` `inbox` `map` (see **Kinds**, **Maps**) |
| `title` | string | yes | all | unique case-insensitively; aliases allowed |
| `summary` | string ≤160 | yes | all | one line; what the index shows instead of the file |
| `status` | enum | yes | all | per-type vocabulary below |
| `tags` | string[] | no | all | lowercase kebab-case, no `#` |
| `aliases` | string[] | no | all | alternative titles for link resolution |
| `links` | string[] | no | all | explicit `"[[Title]]"` relations (body wikilinks also count) |
| `area` | `"[[Title]]"` | project: yes; every new note, idea, task, resource: yes | all but area, journal, inbox | the node's category (see **Categories**) |
| `project` | `"[[Title]]"` | no | task, note, idea | parent project |
| `people` | string[] | no | all | `"[[Name]]"` mentions |
| `map` | `"[[Title]]"` | no | area | the map the category belongs to (see **Maps**); absent = the mind map |
| `connects` | string[] | no | map | the maps it is connected to: `"[[Title]]"` of another map, or `mind` for the mind map (see **Maps**) |
| `due` · `scheduled` | `YYYY-MM-DD` | no | task (project: `due` as its deadline) | |
| `completed` | `YYYY-MM-DD` | no | task, project, goal, resource | the day it was finished; kept in step with `status` by the app (see **Status**) |
| `priority` | 1–4 | no | task | 1 = highest |
| `date` | `YYYY-MM-DD` | yes | journal, event | the day it happened |
| `relation` | string | no | person | friend, colleague, doctor… |
| `url` | string | no | resource | |
| `color` | `#rgb` / `#rrggbb` | no | area, map | the base colour of a category, or of a map's island, in the graph (UI-DESIGN "Colour"); omitted = the UI's sequence, and a category in a map takes the map's |
| `created` · `updated` | ISO 8601 with offset | yes | all | app fills if missing |
| `source` | enum | no | all | `capture` `brain` `manual` `import` (default `manual`) |

**Status vocabulary:** note/idea/area/person/event/map: `active` `archived` · resource: `active` (saved for later) `doing` `done` `archived` · task: `todo` `doing` `done` `dropped` · project: `active` `paused` `done` `archived` · goal: `active` `achieved` `paused` `dropped` · habit: `active` `paused` `archived` · journal: `active` · inbox: `new` `filed`. An inbox item is consumed by the app, never deleted by the brain: `/capture` sets `status: filed` once the content is filed, and the server deletes filed inbox files (and the file a run was started for from the Inbox view, once the run changed anything) before the run's commit, so the original stays in git history.

**Finished vs. archived.** `done` and `achieved` are history: the item stays (faded on the map, under "Done" in its category, UI-DESIGN "Done and archived") and carries `completed` — `withCompleted` in core sets it to the day the status changed (the day of the last edit when healing older files, `healNode`) and removes it when the item opens again; the brain may write it too. `archived` and `dropped` are out of the way. **Retired** (core `retired.ts` `isRetired`): archived, dropped, or done / achieved at least 30 days ago. A retired node sits switched off in the map's archive corner (UI-DESIGN "Done and archived") and leaves every index file but `index/archive.md`; its file stays as it is. Closing something is a status change on the same node; nothing is deleted for it. The full review (`/review`) archives what is obsolete by its rules and asks about the rest.

**Body:** Markdown. Links are `[[Title]]`, `[[Title|shown text]]`, `[[Title#Heading]]`. Links inside frontmatter must be quoted (`"[[Title]]"`). Tasks may use `- [ ]` checklists for sub-steps; the node's own `status` is authoritative.

**History.** What happens to a node after it was created goes at the end of its body as dated lines, one per change, in the user's words — `- 2026-10-29: کفش را خریدم.` — appended by the brain whenever it updates a node from conversation (and by anyone else who likes). The UI lifts these lines out of the text and shows them as the item's timeline between the day it was created and the day it was finished (UI-DESIGN "Item details"); earlier lines are never rewritten.

Example:

```markdown
---
id: 01JBFX6Q2Z5R8K3M9W1T4V7N0A
type: task
title: تماس با دکتر رضایی
summary: نوبت معاینه‌ی سالانه بگیرم؛ ترجیحاً صبح هفته‌ی بعد.
status: todo
tags: [health]
area: "[[سلامتی]]"
people: ["[[دکتر رضایی]]"]
due: 2026-11-05
priority: 2
created: 2026-10-31T10:12:00+03:30
updated: 2026-10-31T10:12:00+03:30
source: capture
---
شماره‌ی مطب در [[دکتر رضایی]] هست. بعد از تماس، نتیجه را در ژورنال امروز بنویس.
```

## Renames

Changing a node's `title` (`PUT /api/nodes/:id` with a new `title`) keeps the file name and rewrites every reference that resolves to the node — body links `[[Old]]`, `[[Old|alias]]`, `[[Old#Heading]]` and quoted frontmatter values (`area`, `project`, `people`, `links`) — as raw text in the files that link to it (fenced and inline code are left alone, nothing else in those files is re-serialized, their `updated` stays). The old title is added to the node's `aliases`, so links written later from memory still resolve. A title that another node already carries (case-insensitively) is refused (409). The whole operation is one vault commit, `manual: rename <old> → <new>`, after a snapshot of pending edits.

## Kinds

Not everything is a task: each kind of thing has its own fields, and the app shows each kind its own way (UI-DESIGN "Kinds"). The fields are ordinary frontmatter keys — Obsidian reads them as properties — validated and completed by `packages/core/src/facets.ts` for the UI (`facets` in `graph.json`).

| Kind (`type`, folder) | For | Kind fields |
|---|---|---|
| `note` (`notes/`) | knowledge, facts, meeting outcomes | — |
| `idea` (`ideas/`) | a possibility worth keeping | — |
| `task` (`tasks/`) | one action | `due`, `scheduled`, `priority` |
| `project` (`projects/`) | an outcome with several steps | `due` (deadline); its tasks name it in `project` |
| `goal` (`goals/`) | something to reach, measured | `target` (`YYYY-MM-DD`), `progress` (0–100), `why` (one line) |
| `habit` (`habits/`) | a routine to repeat | `cadence` (`daily` · `weekly` · `weekdays` · days like `sat,mon,wed` · `3/week`), `time` (`morning` · `afternoon` · `evening` · `night` · `HH:mm`), `checkins` (list of `YYYY-MM-DD`, one per day it was done) |
| `event` (`events/`) | a moment that happened: a memory, a talk, a feeling about it | `date`, `place`, `mood` (`great` · `good` · `okay` · `low` · `bad`); the people in `people` |
| `person` (`people/`) | someone in your life and your relationship | `relation`, `birthday` (`YYYY-MM-DD` or `MM-DD`), `contact`, `met` (how and when you met) |
| `resource` (`resources/`) | a link or thing to read, watch, take or use | `url`, `kind` (`video` · `reel` · `course` · `article` · `book` · `podcast` · `tool` · `other`), `platform` (`instagram` · `youtube` · `aparat` · `coursera` · `udemy` · …), `image`, `duration`, `creator` |
| `journal` (`journal/`) | the day's diary | `date`, `mood` |
| `area` (`areas/`) | a category (see **Categories**) | `color`, `map` |
| `map` (`maps/`) | a space of categories beside the mind map (see **Maps**) | `connects`, `role` (`character` on the one map the brain writes about the owner), `symbol` (the mark at its island's centre: `person` · `star` · `briefcase` · `store` · `camera` · `globe` · `book` · `heart` · `music` · `code`; `person` by default for the character map, `star` otherwise), `color` (its island's colour) |

Derived for the UI: a resource without `platform`/`kind` gets them from its URL (`platformOf`, `kindFromUrl`); a habit's streak and "done today" come from `checkins` (`habitStats`). Feelings about a person are `event` nodes linked to that person (`people`), not tasks; the relationship itself lives on the person.

**Changing a kind** (`PUT /api/nodes/:id` with another `type`): the file moves to the new kind's folder under the same `id` and `title`, so every link keeps resolving; a status the new kind does not know becomes its default; kind fields the new kind does not use stay in the frontmatter. Only the nine kinds above with a plain folder take part — `journal`, `inbox` and `area` are neither a source nor a target. One vault commit, `manual: change kind <title> → <type>`.

**Body lead-ins** (the outcome of a project, why an idea matters) are written in the node's language — «نتیجه:», «قدم بعد:», «چرا مهم است:» on Persian nodes; "Outcome:", "Next action:", "Why it matters:" on English ones — so a Persian note never opens with a Latin label.

## Categories (derived)

A category is an `area` node (Work, Learning, Health…); the graph draws one region and one colour family per category. Every node gets `category` (the area's id) and `categorySource` in `graph.json`, computed by `packages/core` `assignCategories` in this order:

1. an area is its own category (`self`);
2. a node with `area` takes that area (`area`);
3. a node with `project` takes the project's category (`project`);
4. any other node — people and ghosts included — takes the category with the largest edge weight among its neighbours (`belongs_to` 3, `link` 1, `mentions` 1), repeated until nothing changes; ties go to the older category (`links`);
5. `inbox` and `journal` nodes, and nodes with no categorized neighbour, have `category: null` — the UI shows them as the Inbox, Journal and Unsorted groups.

`graph.json` also lists `categories`: `{ id, title, summary, status, color, order, size, map }` with `order` = position by `created` (then id, which is time-sortable), which keeps colours and regions stable when a category is added, and `color` taken from the area's frontmatter when it is a valid hex colour. The brain's `/capture` sets `area` on every node it creates (creating a new area when nothing fits), so inference only fills gaps in hand-written or older files.

## Maps (derived)

A map is a space of categories beside the mind map — the **character map** the brain builds about the owner, a business, a page — kept as a `map` node (`nodes/maps/<slug>.md`, UI-DESIGN "Maps"). A category joins a map through its `map: "[[Map title]]"`; everything the graph assigns to that category is in the map (`map` on every node and category in `graph.json`, null on the mind map). An item never carries `map` itself, and a map node is never an item of a category (it is drawn as the island's outline, not as a dot).

**Connections.** `connects` lists the maps a map is linked to — other maps by title, the mind map as `mind` — and a connection named on either map counts for both (`packages/core/src/maps.ts` `buildMaps`). Connected maps sit side by side on the canvas with their cross links drawn; the brain may use one map's items while working in the other (`/make`, `/advise`, linking). Unconnected maps are islands: their cross links are neither drawn nor laid out, and the brain links within each one only. Toggling a connection is an edit of `connects` (`PUT /api/nodes/:id`): connecting writes the other map onto one side, disconnecting removes it from both.

**Switched off.** `apart: true` on a map is its island's switch turned off (UI-DESIGN "Maps" → The switch): the map counts as connected to nothing and no other map counts it, while every `connects` stays as written on both sides; removing the key switches it on and each connection is back as it was. The switch writes only that key — plus `connects: [mind, …]` when a map with no link to the mind map is switched on — and connecting a switched-off map from a connection chip switches it on. `INDEX.md` marks such a map "switched off" (and "(switched off)" after its name in another map's connections), so the brain treats it as cut off.

**Scopes.** Connections also bound a brain run (UI-DESIGN "Scopes"): the *core* is the mind map plus every map connected to it, directly or through another map; each group of maps cut off from the mind map is a scope of its own (`packages/core/src/maps.ts` `scopesOf`). A run names its scope (`POST /api/brain/run {scope}`: `mind` or the id of a cut-off map), the server writes a **Scope** line into the runtime context, and the brain never reads, files into or links to a map outside it. With one core no line is written and the brain decides per item which space it belongs to.

**The character map** is the one map with `role: character`, built and refreshed by the `/character` skill from the whole vault — categories Traits, Values, Concerns, Voice (Persian «ویژگی‌ها», «ارزش‌ها», «دغدغه‌ها», «لحن»), each item a `note` whose body cites its evidence — and connected to `mind` by default. From conversation the brain adds to it only when the user says so. A map is a separate world of the user's with parts of its own — a business, a brand or a page, a client, a big project — never a topic (a topic is a category). The brain makes one when the user asks (the UI's New map, or in words: «یه جزیره‌ی جدا براش بساز»), or when a message opens such a world without saying where it goes — then only after asking one short question (a new island connected to the mind map, or a category in it) and hearing yes; it files nothing for that world until the answer. A new map is connected to `mind` unless the user wants it apart (template: `.claude/rules/maps.md`, the capture skill's step 4).

`graph.json` lists `maps`: `{ id, title, summary, status, role, symbol, color, connects, apart, kept, order, areas, size }` with `symbol` resolved to its default when unset, `color` the map's own colour (lower-case) or null, `connects` the live connections resolved to ids (`mind` for the mind map; none while either side is switched off), `apart` the switch, `kept` every written connection from either side, paused ones included, `order` by `created`, `areas` the number of its categories and `size` the nodes in them (the areas included). Deleting a map (`DELETE /api/nodes/:id`) returns its categories to the mind map (their `map` is removed); nothing else is touched.

## Related nodes (derived)

`GET /api/nodes/:id/related` suggests nodes that are lexically similar but not linked: the node's own terms form the query (title and tags weigh 3, aliases and summary 2, body occurrences 1 up to 4; English and Persian stop words, numbers and URLs dropped; top 40 terms) and candidates are ranked by BM25 over the MiniSearch index (boosts: title 3, tags 3, summary 2, aliases 2). Excluded: the node itself, nodes linked in either direction, `inbox` and `journal` nodes, pairs dismissed in `.synapse/suggestions.json`, hits below score 1. Each hit carries the shared terms as the "why". Embeddings come later with an API-key engine.

## Links and resolution

Resolution follows Obsidian's model: a link text resolves to a node whose `title` or one of its `aliases` matches case-insensitively after NFC normalization and whitespace trimming; `#Heading` subpaths are ignored for resolution. Unresolved links are kept and shown as **ghost nodes** (id `ghost:<normalized text>`), so the brain or user can materialize them. `resolvedLinks`/`unresolvedLinks` maps (source path → target → count) are kept like Obsidian's MetadataCache.

## Edges (derived)

| kind | from | source of truth |
|---|---|---|
| `link` | any → any | body wikilinks + `links` frontmatter |
| `belongs_to` | task/note/idea → project; project/task → area; area → map | `project`, `area`, `map` fields |
| `mentions` | any → person | `people` field (and body links to person nodes stay `link`) |
| `tag` | node → tag node | UI-side toggle; tags are not nodes in files |

## Index (generated)

`index/INDEX.md` — a router the brain reads first (target ≤ 1.5k tokens):

```
# Vault index (generated <ISO time>; do not edit)
Nodes: N (notes a · ideas b · tasks c · projects d · areas e · people f · journal g · resources h) · inbox: i · archived: x (listed last in each sub-index) · unresolved links: u

## Areas (e) — the mind map's categories; each has a sub-index with every item in it, one line each
- [[Title]] — summary · projects: n · open tasks: m → index/by-area/<area>.md
## Maps (m) — spaces beside the mind map, each with its own categories; file into a map's categories, link across maps only where they connect
- [[Map]] — summary · character (written by /character) · connects: mind, [[Other map]]
  - [[Category]] — summary · items: n → index/by-area/<area>.md
## Active projects (k)
- [[Title]] — summary · area: [[A]] · open tasks: m · next: [[T]]
## Tasks: open n (overdue o, due today t, doing d) → index/by-type/task.md
- [[Title]] — due YYYY-MM-DD · [[Project]]          (overdue + today, ≤10 lines)
## Inbox (i) → nodes/inbox/
- [[Title]] — first line
## Recently updated (10)
- [[Title]] (type) — summary
## Sub-indexes
- index/by-type/note.md (a) · idea.md (b) · task.md (c) · project.md (d) · area.md (e) · person.md (f) · journal.md (g) · resource.md (h)
```

`index/by-type/<type>.md` — one line per live node, sorted by `updated` desc, ending with `Archived: n → index/archive.md` when some of the kind are retired:
`- [[Title]] — summary · status · due:YYYY-MM-DD · completed:YYYY-MM-DD · #tag #tag · people:[[A]],[[B]] · project:[[P]] → nodes/<dir>/<slug>.md`

`index/by-area/<area>.md` — one file per category (`<area>` = the area title's slug), listed from `INDEX.md`'s **Areas** and **Maps** lines: the area's summary (with `· in map [[M]]` for a map's category), then every node the graph assigns to it (**Categories**: explicit `area`, through its project, or inferred from links) under `## <type> (n)` headings in the same line format, and the count of its retired ones.

`index/archive.md` — the retired nodes by kind, in the same line format with `updated:`: kept out of every file the brain reads to work, so a vault's history costs nothing per run; the brain opens it only when the user asks about the past. It is what the brain reads to file into or link inside one category — one short file instead of every by-type list — and the reason index lines carry the people, project and tags of a node: a line alone should say what a node touches.

## Git

Every vault is a git repository (initialized by `create-vault`). `.gitignore`: `index/`, `.synapse/`, `.DS_Store`. Commit prefixes: `brain(capture|ask|chat|advise|make|daily|weekly|insight|character): <summary>` for engine runs, `manual: <summary>` for snapshots of user edits (`manual: rename <old> → <new>` for renames, `manual: update agent layer` for template syncs), `seed: ...` for the sample data. Undo of a brain run = `git revert --no-edit <commit>`.

## Agent layer ownership

`AGENTS.md`, `CLAUDE.md`, `.claude/**` and `.gitignore` ship with the app (`packages/vault-template/template`): `create-vault` copies them into a new vault and the server re-syncs them from the template on every start, so skill and rule updates reach existing vaults. `memory/` and `nodes/` belong to the user and are never touched by the sync.

## Context budget

Always-loaded brain layer (AGENTS.md + CLAUDE.md imports + skill descriptions + rules without `paths:`) ≤ 2.5k tokens, measured by `pnpm vault:context`. `INDEX.md` ≤ 1.5k tokens; when a vault outgrows it, the router keeps counts and pointers only and lists move to sub-indexes.
