# apps/web

- Shell and pages: `App.tsx` + `components/Sidebar.tsx`, pages in `src/views/`, the kinds' cards and detail views in `src/kinds/`, map chrome in `components/graph/`, the WebGL renderer in `src/graph/` (no React inside), the Zustand store in `src/state/`. Network only in `src/lib/api.ts` and `src/lib/ws.ts`; brain runs start through `src/lib/brain.ts` `startRun` (it wires the run, the thread and the recent chats). Spec: `docs/UI-DESIGN.md`.
- Every user-visible string goes through `t()` with the key present in both `src/i18n/fa.ts` and `src/i18n/en.ts` in the same change; remove keys nothing uses. Plain everyday words (UI-DESIGN "Words"): "item"/مورد, never "node"; kinds by their common names. A Latin token with punctuation inside a Persian string gets isolate marks (`⁦…⁩`).
- RTL: logical utilities only (`ms-` `me-` `ps-` `pe-` `start-` `end-` `text-start`); never `ml-`/`mr-`/`left-`/`right-` (the map canvas host and a panel the user drags on it, `MapChat`, are the physical-pixel exceptions). Never put `dir="auto"` on a container: user text goes in `<bdi>`, or — when it truncates or wraps — on the text element itself as `className="… utext" dir="auto"`. Long-form content (Markdown, chat replies, the composer) keeps per-paragraph direction. Buttons that hold a label in a flex row need `text-align: start`.
- Fonts: three roles only — interface (default sans), headings (`font-display` / `var(--font-display)`), reading (`.reading` / `var(--font-reading)`), set by `lib/fonts.ts`. Never hard-code a family, and never add commercial font files (Yekan Bakh, IRANSans) to the repo.
- Kind fields are written as `api.updateNode(id, { frontmatter: { facets: { key: value } } })` with keys from core `FACET_KEYS`; `null`/`''`/`[]` removes one. Every control in a detail view saves on its own.
- Colours: categories, islands and items from `src/graph/colors.ts` (OKLCH tones and families) through `graph/model.ts` `familyTones` and `src/lib/categories.ts` `usePalette()`; never hard-code an item colour. A colour being picked is `store.colorDraft` (drawn at once, written when chosen; `components/ColorPicker.tsx`), and the map takes a colour-only change through `engine.setColors` (`modelShape` unchanged), never `setData`. Spec: UI-DESIGN "Colour".
- Map: React feeds `LivingGraph` data (`graph/model.ts`) and view state; never set React state per frame — per-frame UI (hover card) is updated through refs in `onFrame`. Rebuild GPU buffers only in `setData`. Which labels show is decided in `engine.ts` `updateLabels` by on-screen gap and the names switch (`setNames`; UI-DESIGN "Map-style labels"); `labels.ts` only places them. Keep the frame budget: ≥ 50 fps at 1440×900 on an M1 (measure with `scripts/shoot.mjs --gpu`; the hidden browser pane runs no `requestAnimationFrame`).
- Popovers, dialogs, menus, tooltips: `radix-ui` primitives styled with the CSS classes in `styles/index.css`; panel and message transitions: `motion` (`MotionConfig reducedMotion="user"`). A dialog whose form keeps state is keyed by its props so reopening it with other props starts fresh.
- Kinds' icons are the map's silhouettes (`components/TypeIcon.tsx`, UI-DESIGN "Shapes"); never a lucide icon for a kind. A fact of an item is a chip (`kinds/fields.tsx`: `ChoiceChip`, `DateChip`, `TextChip`, `InfoChip`) in the panel's facts row, not a labelled row.
- Map navigation: every way *into* a category or an item on the map calls `remember(level)` before it flies (`GraphView`), and every way *out* (empty-map click, Escape, back, ✕, the chip toggle) goes through `back()` / `closePlace()`, so the camera returns to where it was (UI-DESIGN "Mind map"). An island's centre and the core are ways in too (levels `item` and `view`). `engine.userMoves` counts only the user's own pans and zooms; app flights frame with `engine.frameNodes`, never `engine.fit` (the user's own move).
- Text fields: `dir={inputDir(value, locale)}` (`lib/format.ts`), never a bare `dir="auto"` on an input or textarea — empty fields must start on the UI side.
- Maps (UI-DESIGN "Maps"): a `map` node is drawn as its island's centre — a hub in its own one-node group (`MAP_GROUP` + id) with its symbol as a DOM glyph over it (`labels.ts` `updateGlyphs`) and its toggle a DOM button placed per frame beside the island by `labels.ts` `updateToggles` (never inside the name label); the mind map's core (`GraphView` `CORE_ID`) and the structure links (core → categories, map → core, map ↔ map) are added client-side in `withStructure`, never in files. An island's regions and items take the map's hue (`colors.ts` `zoneHue`) in both the model and `usePalette`. Cross-map links exist only between connected maps (`engine.setData` drops the rest, so the layout never sees them). Connection toggles write through `lib/maps.ts` `connectionPatches` / `switchPatches`, never a local state; the island's switch writes `apart` and never empties `connects` (VAULT-SPEC "Maps").
- Layout: never call `engine.setData` before the vault's graph has loaded, and keep the saved place, pin and room of a node not on the map (`Layout` seeds) in every snapshot — a layout from no items once wiped the user's spread on every app start. `Layout.setData` keeps every anchor it has (an anchor sticks once computed); never free anchors to move things — a connection change, a new region or a grown one leaves what is on the map where it is, and a refresh that changes nothing must not reheat the simulation (`apps/web/test/layout.test.ts`). The spread and gather tools change a node's `room` (`Layout.spread`, `ROOM_MIN`–`ROOM_MAX`), never an anchor; d3 caches per-node strengths, so a room change goes through `applyRoom`. Saves go through `lib/layout-sync.ts` `LayoutSync` (ARCHITECTURE "Layout"): call `saveLayout()` only after the map itself changed (a drag, a brush click, a settle, a fresh layout) — never on a render, a timer or a refresh, or an idle copy writes its older map over another copy's; a waiting save goes out on `pagehide`, a hidden page and unmount (`leave`, keepalive); another copy's save is taken through `engine.adoptLayout`, which must not reheat (taking must never cause a save).
- The brain at work (UI-DESIGN "Living graph"): `App.tsx` turns a `brain.event`'s `touched` paths into node ids through `lib/activity.ts` `TouchMap` (the core for `index/`, `memory/`, folders and whole-vault searches; a new item's own signal once it is on the map) and announces them on `brainActivity`; `GraphView` forwards them to `engine.signal` and keeps `engine.setWorking` equal to "a run is live". The core is drawn by `graph/brain.ts` (the node shader discards shape 14) and a reach by `graph/arcs.ts`, timed by the pure `planReach`; tune their look in shaders, not in per-frame JS. A waiting or working brain shows `components/BrainWorking.tsx`, never a spinner.
- The ignition (`engine.playIntro`) runs on the first data and whenever the map page becomes active again (`GraphView` `awayRef`); keep new life effects inside it rather than adding a second start animation.
- Scopes (UI-DESIGN "Scopes"): `lib/maps.ts` `scopesOf` mirrors core's; `startRun` sends `scope` only while more than one scope exists, and `ScopePick` renders nothing otherwise — never show a scope choice when everything is connected.
